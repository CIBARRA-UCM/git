Guía interna · flujo con ramas

Del cambio local al merge request

Secuencia de comandos para crear una rama de feature, confirmar tus cambios y subirlos a revisión. Cada bloque tiene su propio botón de copiar, listo para pegar en la terminal.

PS ...\Proyectos GIT\solicitudes-justificacion> git branch * master PS ...\Proyectos GIT\solicitudes-justificacion> git checkout -b feature/deportista Switched to a new branch 'feature/deportista'
1. Ver rama actual 2. Crear rama 3. Ver cambios 4. Preparar cambios 5. Commit 6. Historial 7. Subir rama 8. Merge request
1

Revisa en qué rama estás

Antes de empezar un cambio nuevo, confirma tu punto de partida. El asterisco marca la rama activa.

git branch
2

Crea tu rama de trabajo

Cada funcionalidad o corrección va en su propia rama, con prefijo feature/. El flag -b la crea y te cambia a ella en un solo paso.

git checkout -b feature/nombre-descriptivo

Ejemplo real: git checkout -b feature/deportista

3

Revisa qué cambiaste

Lista los archivos modificados. Todo lo que aparezca en rojo aún no está en staging, así que un commit ahora no lo incluiría.

git status
4

Prepara los cambios (staging)

El punto agrega todo lo modificado en la carpeta actual. Si solo quieres un archivo puntual, reemplázalo por su ruta.

git add .
Nota: los avisos warning: LF will be replaced by CRLF son normales en Windows y no afectan tus archivos; Git solo normaliza los saltos de línea.
5

Confirma el commit

Guarda lo que está en staging con un mensaje breve y claro de qué cambió.

git commit -m "mensaje descriptivo"

Ejemplo real: git commit -m "new deportista destacado"

Si Git pide tu identidad: solo la primera vez en un equipo nuevo. Ejecuta estas dos líneas y vuelve a intentar el commit. 
git config --global user.name "Tu Nombre"
git config --global user.email tu.correo@ucm.cl
6

Revisa el historial

Confirma que tu commit quedó registrado, con autor y fecha correctos, antes de subirlo.

git log
7

Sube la rama al repositorio remoto

--set-upstream vincula tu rama local con el remoto; solo hace falta la primera vez que subes esa rama. GitLab responderá con un enlace directo para crear el merge request.

IMPORTANTE Este comando es solo cuando la rama esta recien creada. el uso normal es solo git push 
git push --set-upstream origin feature/nombre-descriptivo
8

Crea la solicitud de fusión (Merge Request)

Este paso es en GitLab, no en la terminal. Abre el enlace que imprimió el git push anterior, o entra al proyecto y crea la solicitud manualmente:

Defeature/tu-rama
Amaster
Persona asignadatú
Revisorquien revisa el código
Tip: escribe un título y una descripción claros de qué resuelve el cambio; facilita la revisión y queda como registro del proyecto.

Resumen: la secuencia completa

Todos los comandos en orden, listos para copiar de una sola vez.

git branch
git checkout -b feature/nombre-descriptivo
git status
git add .
git commit -m "mensaje descriptivo"
git log
git push --set-upstream origin feature/nombre-descriptivo
Guía de referencia interna para el flujo de trabajo con ramas de feature. Reemplaza los textos en celeste por los valores de tu tarea.
